# Light Stats

Light Stats는 CPU, GPU, 메모리, 디스크, 디스크 I/O, 네트워크, 프록시 경로, 배터리, 온도, 팬, 프로세스, AI 구독 사용량, 그리고 전체 시스템 건강도를 보여주는 컴팩트한 macOS 메뉴 막대 모니터입니다.

## 개요

Light Stats는 핵심 시스템 지표를 메뉴 막대에 상시 표시하고, 더 자세한 정보가 필요할 때 떠 있는 패널을 엽니다. 활성 상태 보기를 계속 열어두지 않고 빠르게 상태를 확인하려는 사용자와, 네이티브 SwiftUI/AppKit 메뉴 막대 모니터링 구현을 참고하려는 개발자를 위해 설계되었습니다.

이 앱은 일상적인 샘플링에 macOS 네이티브 API를 사용하며, 네트워크를 사용하는 진단 기능은 기본적으로 꺼져 있습니다.

## 기능

### 메뉴 막대

- 컴팩트한 2줄 상태 항목
- 고정 너비 값으로 레이아웃 흔들림 방지
- Logo, CPU, GPU, MEM, Disk, Net, Fan, Battery, Health를 선택적으로 표시
- 네트워크 업로드 및 다운로드 속도 표시
- 건강도 점수 선택적 표시

### 개요 패널

- CPU, GPU, 메모리, 부하 평균
- 지원되는 기기에서 배터리 상태, 충전량, 충전 횟수, 건강도, 전력, 온도
- 디스크 사용량 및 집계 디스크 I/O 속도
- 네트워크 속도, 로컬 프록시 상태, 선택적 공개 출구 노드 정보
- 온도, 팬, 디스크 상태 표시줄
- 상위 CPU 프로세스 및 P/E 코어 사용률 차트
- 시스템 건강도 점수 및 항목별 요약
- AI 모니터링을 켜면 Claude Code 및 Codex 구독 사용량 표시

### 메모리 정리

- 메모리 압박 개요
- 스왑 경고
- 메모리 사용량 기준으로 정렬된 앱 목록
- 일반 종료 및 확인 후 강제 종료
- 하위 프로세스 세부 정보 펼치기

### 네트워크 및 프록시

Light Stats는 환경 변수, 시스템 프록시 설정, 활성 터널 인터페이스에서 로컬 프록시 구성을 감지하며, 이 과정에서 외부 요청을 보내지 않습니다.

공개 출구 노드 감지는 선택 사항입니다. 켜면 선택한 geo-IP 공급자에 공개 IP, 위치, ASN, ISP를 조회하고 결과를 캐시하여 반복 요청을 피합니다.

### AI 구독 사용량

켜면 Light Stats는 Claude Code와 Codex CLI가 로컬에 저장한 인증 정보를 읽어 현재 구독 사용률(5시간 및 7일 구간)을 개요 패널에 표시합니다. AI 모니터링은 기본적으로 꺼져 있으며, 인증 정보는 각 공급자 자체의 사용량 엔드포인트 외에는 어디에도 전송되지 않습니다.

### 건강도 점수

건강도 점수는 CPU, 메모리, 부하 평균, 디스크 사용량, 온도, 배터리, 디스크 I/O를 0–100점으로 요약합니다. 기기가 특정 센서를 제공하지 않으면 선택 항목의 가중치가 자동으로 재조정됩니다.

## 개인정보 보호

출구 노드 감지는 기본적으로 꺼져 있습니다. 로컬 프록시 감지는 어떤 외부 서비스에도 연결하지 않습니다.

출구 노드 감지를 켜면 앱이 선택한 geo-IP 공급자에 요청을 보내 현재 공개 IP와 네트워크 소유자를 식별합니다. 결과는 60초 동안 캐시되며, 실패 시 조용히 폴백합니다.

## 설정

- 메뉴 막대 항목 표시 여부
- 새로 고침 속도: 낮음 (5s), 중간 (2s), 높음 (1s)
- 온도 단위: 섭씨 또는 화씨
- 네트워크 속도 단위: 자동, KB/s, MB/s
- 출구 노드 감지 및 공급자 선택
- AI 모니터링 전환 (Claude Code 및 Codex 사용량)
- 언어: 简体中文, English, 日本語, 한국어, 시스템 언어

## 개발

### 요구 사항

- macOS 14+ (macOS 26 Liquid Glass 비주얼 스타일 지원)
- Xcode 16 이상 권장
- Swift 5.9+

### 기술 스택

- 패널 및 설정에 SwiftUI
- 메뉴 막대 통합 및 커스텀 드로잉에 AppKit
- Combine 및 Swift Concurrency
- Mach API, IOKit, CFNetwork, Network, SMC, getifaddrs

### 아키텍처

앱은 모델, 서비스, 뷰 모델, 뷰 계층으로 분리되어 있습니다. `SystemMonitor`가 샘플링을 조율하여 UI에 스냅샷을 발행하고, 각 서비스 타입이 해당 지표를 수집합니다.

캐시되거나 비동기적인 수집기(출구 노드, 배터리 스마트 데이터 리더 등)는 actor를 사용합니다. 가벼운 로컬 헬퍼는 적절한 경우 동기로 유지됩니다.

### 프로젝트 구조

- `Light Stats/Models/`: 지표 데이터 구조
- `Light Stats/Services/`: 시스템 데이터 수집 및 점수 계산
- `Light Stats/ViewModels/`: 앱 상태 및 샘플링 조율
- `Light Stats/Views/StatusBar/`: 메뉴 막대 렌더링
- `Light Stats/Views/Popover/`: 떠 있는 패널 UI
- `Light Stats/Views/Settings/`: 설정 UI
- `Light Stats/Resources/`: 현지화 문자열
