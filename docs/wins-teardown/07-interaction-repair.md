# 窗口管理交互修复记录

日期：2026-09-15。依据：用户对原交付的实际反馈、三张 Wins 参考截图，以及 `录屏2026-09-15 03.30.55.mov`（37.09 秒）。原 session 的“全部完成”不是本轮的验收结论。

## 悬浮岛与边缘分区

悬浮岛改为一排直接可投放的布局。无需先选择布局，再到另一区域选择窗格。`SnapIslandLayout.tiles/hit` 共用矩形，`SnapLayoutProjection` 将实际屏幕上的落位与间距等比投影到缩略图。展开期间面板保持最终坐标，动画改变顶部居中的可见区域，窗格不会随面板缩放而滑移。

录屏中的稳定形态包括：14 秒附近的上半屏、16 秒附近的左半屏、18 秒附近的下半屏、20 秒附近的左下四分屏、22–23 秒附近的左侧三分之二、24–26 秒附近的右侧三分之一、32 秒附近的中间三分之一、34 秒附近的左侧三分之一。过渡中的矩形不作为独立布局。

本轮边缘表提供 14 种不同落位结果：

| 位置 | 结果 |
|---|---|
| 四角 | 对应四分之一 |
| 左右边缘上段 | 上半屏 |
| 左右边缘中段 | 对应左右半屏 |
| 左右边缘下段 | 下半屏 |
| 底边由左至右五段 | 左 1/3、左 2/3、中 1/3、右 2/3、右 1/3 |
| 顶部 | 悬浮岛或最大化，遵循设置 |

分区表位于 `SnapEdgeRegionCatalog`。侧边分界采用 18% / 82%，底边采用五段，角区最大 48 pt；这些是根据录屏确定的本地调校值，并非声称从 Wins 提取到了精确常量。`SnapZonePolicy` 为相邻分区保留 6 pt 稳定区；四角和悬浮岛优先。设置演示、实际拖动和松手使用同一套表及稳定区。

预览使用 `NSVisualEffectView` 毛玻璃窗口；明确启用图层。换目标时从已经显示的矩形及透明度接续动画，避免淡入被重置或位置跳变。减少动态效果采用短时间线。

## 已修复的断链

- 松手不再依赖“仍处于顶部触发带”。主线程在真实 mouse-up 位置判定岛内窗格；岛内缝隙取消，岛外仍可落到边缘目标。
- 拖动结束、关闭功能或开始新拖动后，旧的异步 AX 结果及待交付更新被代次检查丢弃。
- 鼠标按下即开始解析窗口；同一时刻只允许一个帧采样请求，最多 30 Hz。AX 命中失败时补充 WindowServer → 对应应用窗口的解析路径。
- 原有 12 pt 边缘阈值在运行时提升至至少 24 pt；没有依靠不停扩大角区来获得灵敏度。
- 悬浮岛展开接续淡入时，同时维护透明度，避免取消淡入后留在透明状态。
- 新配置不能在窗口管理总开关关闭时重新注册快捷键。
- 摇动单独启用时仍运行拖动监测；全部取消固定布局的选择能够跨重启保存。

## 布局编辑与快捷键

8×8 编辑器支持多个区域、选中、移动、拖角缩放、删除、撤销、编辑已有布局、固定与排序。区域重叠会被拒绝；网格手势每次重新锚定。保存位置已有创建入口和直接录制快捷键的入口。删除位置不会误删仍被布局使用的区域快捷键。

快捷键以一次完整组合提交；改绑同一组合时移除旧动作的绑定。自定义布局的每个区域都可在快捷键列表中找到。关闭窗口、退出应用为显式录制的动作，没有默认快捷键，使用正常关闭/退出请求。

## 真实预览与延迟

旧路径在全应用 AX 枚举之后才提供预览数据，并与拖动/落位串行竞争；嵌套访问队列还被错误地连续记为 error。

新路径以一次 WindowServer 快照构建预览目录，在用户真正选择窗口时再解析其 AX 元素。最小化、全屏和不能分屏的普通应用窗口仍可预览。匹配时优先身份和标题，不把两个同尺寸最大化窗口当成同一个窗口。

ScreenCaptureKit 提供真实图像；不是示意窗格。截图与窗口枚举请求合并，最近应用的首个窗口提前预热。可滚动的惰性窗口行只为附近的卡片加载图像。缓存最多 48 项、有效期 4 秒，较大的新鲜图片可复用；关闭面板释放视图并安排过期清理，关闭缩略图时立即清空。未得到图像时显示加载或不可用状态，不绘制假窗口图像。

Cmd-Tab 修复首次跳过上一应用的重复前进，反向开始位置与过期 UI 更新也分别处理。窗口数量较多时，应用行与窗口行会滚动到当前选择。

Dock 悬停采用 180 ms 进入延迟与 250 ms 离开宽限；30 Hz 采样中，静止指针的 AX 探测结果复用 250 ms。图标与面板之间的空隙不会立即取消预览。
