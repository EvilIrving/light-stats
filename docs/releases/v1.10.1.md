## Light Stats 1.10.1

修一个能看见的失效：Cursor 更新之后，AI 用量里的 Cursor 卡片读不出数字了。原因是 Cursor 自 3.27 起把登录凭据加密存进钥匙串，原来那套读明文凭据、再带网页 cookie 请求用量的做法全部落空。现在按 Cursor 桌面端自己的方式走：从钥匙串解开凭据，直接调它的用量接口，不再拼 cookie。升级后第一次读取，系统会问一次是否允许 Light Stats 读取 Cursor 的登录信息，选「始终允许」之后就不再打扰。

One visible break fixed: after a Cursor update, the Cursor card in AI Usage stopped showing numbers. Cursor has encrypted its sign-in credential into the macOS Keychain since 3.27, so reading a plaintext token and requesting usage with a browser cookie no longer worked. It now takes the same route Cursor's own app takes — unlock the credential from the Keychain and call Cursor's usage endpoint directly, with no cookie involved. On the first read after upgrading, macOS asks once whether Light Stats may read Cursor's sign-in information; choosing "Always Allow" is the last time you see it.

### 修复

- Cursor 用量恢复显示：凭据从钥匙串解密，请求走 Cursor 的用量接口，不再依赖网页 cookie / Cursor usage works again: the credential is decrypted from the Keychain and the request goes to Cursor's usage endpoint, with no web cookie involved
- 面板不再把「读不出凭据」和「凭据是错的」混成一句提示：钥匙串被拒绝时直接说清要允许什么 / The panel no longer collapses "the credential cannot be read" into "the credential is wrong": a refused Keychain read says plainly what to allow

### 改进

- 按老套餐计费的账号，Cursor 卡片多出一行「总量」，与 Cursor 自己的仪表盘口径一致；统一套餐账号仍是一根周窗口 / Accounts on the older billing get a "Usage" total row on the Cursor card, matching Cursor's own dashboard; unified accounts still show a single weekly bar
