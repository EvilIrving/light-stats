## Light Stats 1.9.10

这一版让清理页的「后台进程」行真正说清楚自己装了什么。后台进程不再堆成一串看不懂的可执行文件：它们按所属的已安装应用分组，每组一段标题，带上该组的进程数与内存小计，没有任何已安装应用认领的进程归入「无归属」。归属不依赖进程是否在运行——helper 的归属来自它所在的 bundle，装在 bundle 之外的特权 helper 则来自它自己的 launchd 任务名（去掉 `helper`、`daemon` 这类角色后缀后剩下的就是产品）。展开的应用行也一并修好了命名与计数：嵌套的 helper bundle 指出成员名（`Figma Helper (Renderer)` 而不是再次出现宿主应用名），没有自己 bundle 的 helper 用可执行文件名，只有重名的成员才附带 PID，悬停显示完整路径；展开列表现在包含该应用自身的进程，与行上显示的数量一致。

This release makes the Cleanup tab's background process row say what it actually holds. Background processes are no longer an undifferentiated list of executable names: they are grouped under the installed application behind them, each group with a header carrying its process count and memory subtotal, and anything no installed application claims falls under one Unattributed section. Attribution does not require the application to be running — a helper is attributed through the bundle it lives in, and a privileged helper installed outside every bundle through the name of its own launchd job, with role suffixes such as `helper` and `daemon` stripped down to the product. Expanded application rows got the matching naming and counting fixes: a nested helper bundle names the member (`Figma Helper (Renderer)` rather than the host application's name again), a helper with no bundle of its own is named by its executable, only same-named members carry a PID, hovering shows the full path, and the expanded list now includes the application's own process, so it matches the count on the row.

### 新增

- 后台进程按所属已安装应用分组，每组显示名称、进程数与内存小计 / Background processes grouped by their owning installed application, each group showing its name, process count, and memory subtotal
- 归属同时读进程所在 bundle 与 launchd 任务名：装在 bundle 外、没有任何运行中应用认领的特权 helper 也能显示所属产品 / Attribution reads both the process's bundle and its launchd job label, so a privileged helper installed outside every bundle still shows the product it belongs to
- 无法归属的进程统一归入「无归属」段 / Processes nothing installed claims stay together under one Unattributed section

### 改进

- 展开行的成员名：嵌套 helper bundle 指出成员本身，没有 bundle 的 helper 用可执行文件名 / Member lines in an expanded row: a nested helper bundle names the member, and a helper without one is named by its executable
- 只有重名的成员才附带 PID，避免列表里出现一串难以分辨的相同名称 / Only same-named members carry a PID, so a list of identical labels stays readable
- 悬停成员行显示完整命令行路径 / Hovering a member line shows its full command path
- 每组的内存小计沿用全局口径：读数缺失时显示 `≥` 或 `—`，不以 0 冒充实测 / A group's memory subtotal keeps the app-wide rule: `≥` or `—` when readings are missing, never 0 as a stand-in
- 后台进程仍是单独一行，分组只是给进程加标签，不会多出可关闭的条目 / The background row stays a single row; a section labels its processes instead of adding another closable entry

### 修复

- 展开列表包含该应用自身的进程，数量与行上显示的一致（此前少一个）/ An expanded list includes the application's own process, matching the row's count (previously one short)
- 后台进程的名单过滤（`watchman` 一类按进程名排除的规则）此前收到的是完整路径，从未命中，这些进程会出现在列表里 / The background list's name-based exclusions (such as `watchman`) received a full path and never matched, so those processes appeared in the list
